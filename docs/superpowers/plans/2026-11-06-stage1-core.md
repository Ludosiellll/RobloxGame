# Этап 1 «Метеоритного дождя» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** играбельное ядро на большой трассе миров: метеориты с брейнротами падают по зонам с эффектами из паков Fireball/Thunderstorm, их несут на базу, отнимают толчком, существа анимированы и приносят деньги, прогресс сохраняется.

**Architecture:** функциональное ядро + тонкая оболочка. Все решения (случайности, формулы, данные, блокировки, выборка кадров анимации) — чистые модули в `src/shared`, их тесты гоняются в Node через luau-web и в Studio. Сервисы на сервере и контроллеры на клиенте только связывают ядро с Roblox API. Сервер решает всё, клиент рисует.

**Tech Stack:** Luau (`--!strict`), Rojo 7.6.1, luau-web 1.5.1 (Node, только для тестов), DataStoreService, ProximityPrompt, ParticleEmitter, Bone.Transform.

**Spec:** `docs/superpowers/specs/2026-11-06-meteor-rain-expanded-design.md` (разделы 2–4, 5 без продажи, 12–13). Опись ассетов: `docs/assets/INVENTORY.md`.

## Global Constraints

- Главная цель продукта: чтобы как можно больше людей захотели играть и покупали за Robux. Каждая фича этапа должна давать заметный «вау»-момент (падение, раскрытие существа, редкая находка видна всем). Параметры `luck` и `incomeMultiplier` есть в формулах уже сейчас — на них потом сядут покупки.
- Язык игры — английский. Все строки в интерфейсе на английском.
- Каждый `.luau` файл начинается с `--!strict`.
- Сервер не доверяет клиенту: каждый RemoteEvent проверяет типы, значения и частоту.
- `main` всегда рабочая: после каждой задачи `node tools/luau-test/run.mjs` зелёный, Rojo-проект собирается.
- Rojo управляет только `ReplicatedStorage.Shared`, `ServerScriptService.Server`, `ServerScriptService.Tests`, `StarterPlayer.StarterPlayerScripts.Client`, `ServerStorage.Packs`. Всё, что код создаёт во время игры, кладётся в `ReplicatedStorage.Runtime` / `workspace.Runtime`.
- Чистые модули не трогают `game`, `workspace`, `Instance`, `Vector3`, `CFrame`, `task`, `os.time`: время, случайность и координаты передаются аргументами (`rng: () -> number`, числа `x, z`).
- Карту из старого проекта код не хардкодит: границы зон читает из `workspace.Biomes.<Name>`, базы ставит по `workspace.BaseSlots` (если Денис их расставил) или по раскладке из `Config`.
- `StreamingEnabled = true`: клиент не предполагает, что дальние детали карты загружены; данные зон получает от сервера.
- Studio-only код (`DebugService`, `DebugPanel`, `TestRunner`) включается только при `RunService:IsStudio()`.
- Числа ниже — стартовый баланс, все лежат в `Config` / `Rarity` / `Zones`.

## Review Focus

1. **Игрок выходит или умирает с метеоритом в руках** — метеорит падает на месте как выроненный, никто не остаётся с «призраком» над головой. Чек-лист задачи 13 + тест `Formulas.dropDespawnAt` в задаче 3.
2. **Сохранение не загрузилось (DataStore упал)** — игрока выкидывает с сообщением, пустые данные никогда не пишутся поверх настоящих. Тесты `SessionLock`/`DataSchema` в задаче 4 + чек-лист задачи 6.
3. **Мутированное существо при полной базе** — заменяется самое слабое с учётом мутации, а не по базовой редкости. Тест `Formulas.placeOrReplace` в задаче 3.
4. **Точка падения в воде, лаве или за пределами зоны** — точка отбрасывается, ищется новая; если за 8 попыток не нашлась, падение пропускается без ошибки. Тест `Formulas.isSpawnHitAllowed` в задаче 3.
5. **Ассеты не скопированы в Studio** — игра не падает: `AssetCheck` пишет, чего не хватает и куда положить; метеорит без пака Fireball рисуется запасным шаром, существо без модели — серым кубом с именем. Чек-лист задачи 7.

### Task 3: Формулы и случайные выборы

**Files:**
- Create: `src/shared/Formulas.luau`, `src/shared/Roll.luau`, `tests/Formulas.spec.luau`, `tests/Roll.spec.luau`

**Interfaces:**
- Consumes: `Rarity`, `Zones`, `Creatures`, `Config` (задача 2).
- Produces (`Roll`): `Roll.weighted(weights: {[string]: number}, order: {string}, rng: () -> number): string?`; `Roll.rarity(zoneIndex: number, luck: number, rng): string` (luck ≥ 1 умножает веса всех редкостей кроме Common); `Roll.mutation(zoneIndex: number, luck: number, rng): string?` (шанс каждой мутации × `(1 + ZoneMutationBonus × (zoneIndex − 1)) × luck`, проверка от самой редкой к частой, одна мутация максимум); `Roll.creature(rarity: string, rng): string` (id); `Roll.meteor(zoneIndex, luck, rng): {rarity: string, mutation: string?, creatureId: string}`.
- Produces (`Formulas`): `creatureIncome(creatureId: string, mutation: string?): number`; `incomePerSecond(creatures: {{id: string, mutation: string?}}, rebirths: number, incomeMultiplier: number): number` (сумма × `(1 + IncomeBonus × rebirths)` × multiplier, вниз до целого); `offlineEarnings(incomePerSec: number, secondsAway: number): number` (`floor(income × OfflineRate × min(secondsAway, OfflineMaxHours×3600))`, отрицательное время → 0); `sellValue(creatureId, mutation): number` (`creatureIncome × SellSeconds`); `carryMultiplier(rarity: string, strengthLevel: number): number` (`1 − (1 − carry) × (1 − StrengthPerLevel × min(level, StrengthMaxLevel))`); `placeOrReplace(slots: {{id: string, mutation: string?}}, capacity: number, new: {id: string, mutation: string?}): (action: "place" | "replace" | "sell", index: number?)` — при свободном месте `"place"`; иначе самое слабое по `creatureIncome` с мутацией; если новое ценнее — `"replace", index`, иначе `"sell"`; `zoneAt(z: number, zones: {{minZ: number, maxZ: number}}): number?`; `isSpawnHitAllowed(hitName: string): boolean` (false, если имя содержит любое из `BlockedHitNames`, без учёта регистра); `pushAllowed(dx: number, dz: number, lookX: number, lookZ: number, cooldownLeft: number, targetSafe: boolean): boolean` (дистанция ≤ Range, угол ≤ ConeDegrees/2 от взгляда, кулдаун 0, цель не в безопасной зоне); `speedSuspicious(distance: number, dt: number, walkSpeed: number): boolean` (`distance > walkSpeed × SpeedTolerance × dt + SpeedSlack`); `dropDespawnAt(now: number): number` (`now + DespawnDropped`); `formatMoney(n: number): string` (`999` → «999», `1200` → «1.2K», `3_400_000` → «3.4M», `5.6e9` → «5.6B», `7e12` → «7T»).
